### 本轮测试怎么跑的（沙箱限制，如实记录）

- 这个会话的沙箱不允许进程用管道方式 spawn 子进程，`npm test` 会在 Vite 载入配置阶段报
  `spawn EPERM`（`optimizeSafeRealPathSync` 调 `net use`）。这不是代码问题，项目 README 里也写过。
- 因此我用 `node` 直接加载同一批 `.test.ts` 文件跑：一个 Node loader 把裸模块 `vitest` 指到一个
  **最小的 describe/it/expect 替身**（只实现本项目用到的断言），把无扩展名的相对导入补成 `.ts`。
- 结果：**3 个新测试文件、41 条用例全部通过**（`model.test.ts` 15 条、`chainPath.test.ts` 13 条、
  `controller.test.ts` 13 条）。旧用例（按动笔、GPA、地基）本轮没有重跑，那些代码路径也没有改动。
- 替身与运行脚本放在 `.tmp/`（临时验证工具，验证完已删除，不进项目源码）。正常终端里
  `npx vitest run` 应该直接跑通，但**这一点没有在本轮验证**。

## 三、过程中发现并修掉的问题

1. **StrictMode 双挂载把 WebGL 上下文弄死**（框架层）：`<canvas>` 写在 JSX 里，卸载时
   `forceContextLoss()` 让同一块画布永久不可用。改为每次启动新建画布 + 移除。
2. **自动按压不提交**：动画时间轴的「回程」段忘了把方向切成 `up`，提交判据和索引第二段
   都不生效。由单测「按一下并释放后保持出芯」发现，改为段内带方向。
3. **笔夹挂错方向**：`ExtrudeGeometry` 的截面落在径向平面上，笔夹看起来像贴在笔杆侧面的黑条。
   改为「宽度沿切向、厚度沿径向」，并补了根部座与弹性钢片。
4. **剖视看不到导槽**：固定导向的外圈是整圈，朝向镜头的一半挡住内部。
   改用世界裁剪面（x ≤ 0 保留）切掉近半圈；肋条与斜面同样剖切，转子才能露出来。
5. **透明件挡住拾取**：点透明笔杆只会选中笔杆。改为透明外壳标记 `pickThrough`，
   拾取跳过它们；握胶这类实心件仍然正常遮挡。
6. **「拆解」重名**：展示方式与镜头预设都有「拆解」。镜头预设改名「拆解位」。
7. **模型时间显示成位移**：播放条前缀写死「模型时间」。增加 `timeLabelPrefix`，按动笔用「机构位移」。
8. **切回自由探索不恢复播放**：模式切换只处理了「暂停」没处理「播放」。已补。
9. **展开图左侧标注被裁掉**：绘图区左边距 46 太窄，「4.0 解除导向」被切。加宽到 104 并重排底部坐标轴。

### 画面相关（截图检查过的）

- 整车：车架、前后轮、车把、坐垫、前叉比例正常，传动侧朝外。
- 传动侧：上段从飞轮回到前盘、下段经两个导轮回到前盘，闭合走向正确；链条没有穿过后下叉、辐条或飞轮实体。
- 后方：12 片飞轮排成一列、后拨横向移动可见；链条在所选齿片平面上。
- 后拨放大：四连杆、导板、导向轮、张力轮都能分辨；导板夹在两个导轮外侧，链条从导轮齿上绕过。

### 过程中发现并修掉的问题

1. **齿形画出来大 1000 倍**：`ExtrudeGeometry` 的轮廓是用 mm 画的，直接放进米制场景后前盘直径 178 m。
   改为在挤出后统一 `scale(0.001)`；截图里「整屏被一个灰色曲面糊住」就是这个。
2. **前轮跟着传动转**：台架演示里前轮不该动。改为前轮只由「拨前轮」彩蛋控制。
3. **导向轮几乎没绕上链条**：初版两导轮中心距 90 mm、导向轮后偏 40 mm，导向轮包角只有 3–9°。
   加大中心距到 130 mm、后偏到 48 mm 并重新解链长，包角升到 23–57°，视觉上链条真的绕在导轮上。
4. **`useSyncExternalStore` 无限重渲染**：控制器每次返回新快照对象，React 认为状态一直在变 → 白屏报
   「Maximum update depth exceeded」。改为缓存快照、状态变更时才失效。
5. **切到旁观者模式后镜头被轨道控制拉回去**：`stage3d.render()` 每帧无条件 `controls.update()`。
   加了一个 `if (controls.enabled)` 守卫（按动笔不受影响：它从不关闭轨道控制）。
6. **测试自身的两处断言写错**：接点切向原来拿「第 i 段末尾」比「第 i 段开头」，换挡完成检测漏掉了
   `previous.shifting` 条件。都是断言错，不是实现错，已改为正确比较。
7. **指针锁定在受限容器里被浏览器拒绝**（`WrongDocumentError`）：保留「点击画面锁定鼠标」的主路径，
   同时加了「按住拖动也能环顾」的回退，WASD 不依赖锁定。

## 四、没有验证的

- 真机（iOS / Android 浏览器）上的触摸拖动与长时间性能；窄屏只在桌面浏览器缩到 500 px 检查过。
- 低端集显与软件渲染下的帧率；页面只会显示「软件渲染，可能偏慢」提示，没有实测数据。
- WebGL 上下文真正丢失后的恢复路径：按钮与逻辑已就位，但没有构造真实丢失事件验证。
- 与真实 JJ15 实物的一一对应：内部机构是教学设定，没有拆开实物核对齿形与配合。
- 资料包里的原视频没有做逐帧分析，因此没有从视频得到的任何尺寸或次数结论。
- **变速器的全屏 → 旁观者模式**：代码已接，但本轮没有在真浏览器里点「全屏」验证（受限容器里全屏被拦）。
- **指针锁定**：本轮的测试容器里 `requestPointerLock` 被浏览器拒绝（`WrongDocumentError`），
  所以「锁定后鼠标环顾」这条主路径没有实测；实测的是拖动环顾的回退路径与 WASD 移动。
- 变速器的**真机触屏**：窄屏只看了布局与控件可读，没有在手机上做触摸拖动/双指缩放。
- 变速器的**性能**：120 个链节实例 + 12 片飞轮 + 32 根辐条，没有在本轮测帧率。
- 变速器链条的**逐链节啮合相位**：只保证弧长等距与节圆半径，不保证每个滚子精确落进每个齿谷。
